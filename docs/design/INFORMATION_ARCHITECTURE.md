# Information Architecture

## Page structure

```
┌─────────────────────────────────────────────────────────────────┐
│  <header>                                                        │
│    owlcompare wordmark                                           │
│    Title: "Diff: source_A → source_B"                           │
│    StatusBadge: "1 breaking change" (red)  or  "No breaking" (gn)│
│    Toolbar: [Download JSON] [Copy link] [◐ theme]               │
├─────────────────────────────────────────────────────────────────┤
│  Summary strip (sticky on scroll)                                │
│    Breaking 1 · Non-breaking 1 · Additive 1 · Info 2 · Renames 1 │
├─────────────────────────────────────────────────────────────────┤
│  <main>                                                          │
│    §Renames            (always first, if present)                │
│    §Breaking changes   (open by default)                         │
│    §Other changes      (non-breaking + additive + info)          │
│    §Unexplained Layer 0 (CollapsibleSection, collapsed)          │
├─────────────────────────────────────────────────────────────────┤
│  <footer>                                                        │
│    Generated by owlcompare X.Y.Z · Schema · GitHub · schema_ver  │
└─────────────────────────────────────────────────────────────────┘
```

The filter **sidebar is deferred to v1.1** (see Open Questions Q2). v1 ships the
single scrolling column above. The IA leaves room for a left sidebar without a
structural rewrite: `<main>` is a single column today and becomes the right cell
of a two-column grid later.

## Navigation model: single-page, scroll-anchored

One scrollable document. No tabs, no SPA router. Every section carries a stable
`id` (`#renames`, `#breaking`, `#other`, `#layer0`). The sticky summary strip
counts double as fragment links to those sections. Each change has its own
`id` derived from its `change_id` so a CI log or a colleague can deep-link to a
single change.

## The four IA decisions

- **Single-page, not multi-tab.** A report is *a file*. Someone attaches it to a
  PR, mails it, or commits it. Tabs imply state that does not survive "Save As" or
  re-opening from disk, so the document is flat and self-contained.
- **Scroll-anchored, not SPA routing.** In-file SPA routing is fragile across
  `file://`, email previews, and corporate proxies, and it breaks `Ctrl-F`. Story
  2 lives and dies by browser find, so the entire change set is always in the DOM.
- **Severity-grouped, not entity-grouped.** Four of five stories ask "what's
  broken?" first. Severity is the primary axis; the secondary entity-centric view
  (story 2) is served by `Ctrl-F` in v1 and the namespace/kind filter in v1.1.
- **Progressively disclosed, not paginated.** Real diffs run to dozens or a few
  hundred changes. Pagination splits context across pages and defeats find;
  instead sections collapse/expand and long sections cap at 50 visible with an
  "…and N more" affordance, keeping everything on one searchable page.

## Story → IA traceability

| Story | Served by |
|-------|-----------|
| 1 Reviewer skim | Header status badge + Breaking section open by default, both above the fold. |
| 2 Integrator deep-dive | All changes in-DOM + per-change expansion + selectable IRIs (`Ctrl-F`). |
| 3 Historian | Renames section first; top-to-bottom narrative ordering. |
| 4 CI debugger | Per-change severity-refinement note + deep-linkable change `id`. |
| 5 Architect's audit | Sticky summary strip with per-severity counts (single-report scope). |

No story requires a pattern the IA lacks; story 5's cross-report aggregation is
explicitly out of v1 scope, not an unmet IA requirement.
