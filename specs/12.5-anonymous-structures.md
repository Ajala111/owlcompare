# Component 12.5: Anonymous Structure Decoding

## Identity

- **Component number:** 12.5 (inserted between rename refinements and the renderer phase to address correctness gaps before user-visible rendering)
- **Name:** Anonymous structure decoding (union sets, datatype facets, isReplacedBy)
- **Module paths:**
  - `src/owlcompare/diff/structural/_class_set_index.py` — decoder for anonymous union/intersection structures
  - `src/owlcompare/diff/structural/_datatype_facet_index.py` — decoder for `owl:onDatatype` + `owl:withRestrictions` shapes
  - `src/owlcompare/diff/structural/class_sets.py` — Layer 1 slice emitting the new change kinds
  - `src/owlcompare/diff/structural/replaced_by.py` — Layer 1 slice for `dcterms:isReplacedBy` semantics
- **Roadmap phase:** Phase 3 (additive — extends rather than replaces Component 12)
- **Depends on components:** 02 (model), 04 (canonicalize, restriction URN format, list URN format), 05–11 (the diff pipeline this extends), 12 (rename detection — `replaced_by` cross-checks against detected renames)
- **Depended on by:** 14 (JSON schema — must include the new change kinds), 15 (Markdown renderer — must render them), 17 (HTML renderer — same), all CI integration

## Purpose

Decode three classes of anonymous OWL/RDFS structures that the existing diff pipeline currently surfaces as raw `_list:` / `_restriction:` Layer 0 noise, and emit them as structured Layer 1 changes:

1. **`owl:unionOf` / `owl:intersectionOf` lists attached to `rdfs:domain`, `rdfs:range`, `rdfs:subClassOf`, or `owl:equivalentClass`.** These are the "this entity points to a *set* of classes" pattern that ERA, FIBO, OBO, and most real-world ontologies use heavily. Today: 5–10 lines of `_list:abc rdf:first ...` noise per change. After this component: one structured change describing what members were added or removed from the set.

2. **`owl:onDatatype` + `owl:withRestrictions` (with `xsd:minInclusive` / `xsd:maxInclusive` facets) attached to `rdfs:range`.** The standard OWL 2 pattern for datatype facet restrictions on data properties. Today: opaque Layer 0 noise. After: structured changes describing facet shifts (`min 0 → min 1`, `max 327670 → max 500000`).

3. **`dcterms:isReplacedBy` annotations.** When a curator asserts that one entity replaces another, that's *semantically* a rename — but it's *evidence* the curator wants visible. Today: emitted as a generic `annotation_added`. After: emitted as a dedicated `replaced_by_set` change, with a flag in `details` if the target is also a detected rename (consistency cross-check).

What would break if we removed this: the HTML report (Component 17) would either render reams of `_list:` URN noise to the user, or hide it and silently lose information. Either is unacceptable for the project's headline use case (railway ontology evolution).

## Public API

```python
# src/owlcompare/diff/structural/class_sets.py

def diff(
    a: OntologySnapshot,
    b: OntologySnapshot,
    layer0_changes: list[Change],
    registry: SubsumptionRegistry,
    options: DiffOptions | None = None,
) -> list[Change]:
    """Detect and emit Layer 1 changes for anonymous class-set structures.

    Handles owl:unionOf and owl:intersectionOf attached to:
      - rdfs:domain     -> domain_union_changed / domain_union_added / domain_union_removed
      - rdfs:range      -> range_union_changed / range_union_added / range_union_removed
      - rdfs:subClassOf -> subclass_union_changed / subclass_union_added / subclass_union_removed
      - owl:equivalentClass -> equivalent_class_union_changed / _added / _removed

    Also handles the flattening/unflattening case (union with one remaining
    member normalizes to the bare member).
    """


# src/owlcompare/diff/structural/replaced_by.py

def diff(
    a: OntologySnapshot,
    b: OntologySnapshot,
    layer0_changes: list[Change],
    registry: SubsumptionRegistry,
    renames_applied: tuple,
    options: DiffOptions | None = None,
) -> list[Change]:
    """Detect dcterms:isReplacedBy assertions added or removed.

    Emits:
      - replaced_by_set: entity newly asserted to be replaced by another
      - replaced_by_unset: assertion removed (rare)

    Cross-references renames_applied: if the assertion target matches a
    detected rename's after_iri, mark details.matches_detected_rename = True.
    """
```

These two slices are added to the orchestrator pipeline between `restrictions.diff` and `annotations.diff`:

```
... → restrictions.diff → class_sets.diff → replaced_by.diff → annotations.diff → renames → severity
```

This ordering matters because:
- `class_sets.diff` must run after `restrictions.diff` (which already consumes the simple-form restriction URN triples)
- `class_sets.diff` must run before `annotations.diff` (because some Layer 0 changes will now be subsumed under union-changed kinds rather than annotations)
- `replaced_by.diff` must run after rename detection won't actually — see internal design note below

Wait: **`replaced_by` cross-checking against `renames_applied` needs renames to have run first.** So `replaced_by.diff` runs *after* renames, but the registry from `class_sets.diff` is threaded through.

Final order:

```
... → restrictions.diff → class_sets.diff → annotations.diff → renames.detect → replaced_by.diff → severity
```

The `replaced_by` slice runs late so it can read `renames_applied` from the result-in-progress.

## Internal design

### Part 1 — Class set index

`_class_set_index.py` produces a per-snapshot structured view of every anonymous class-set attached to a named entity via one of the four predicates:

```python
@dataclass(frozen=True, slots=True)
class ClassSetAttachment:
    """An owl:unionOf or owl:intersectionOf set attached to a named entity."""
    attached_to: str               # IRI of the named entity (the subject)
    via_predicate: Literal[
        "rdfs:domain", "rdfs:range", "rdfs:subClassOf", "owl:equivalentClass"
    ]
    operator: Literal["unionOf", "intersectionOf"]
    member_iris: tuple[str, ...]   # sorted tuple of named entity IRIs
    raw_urn: str | None            # the urn:owlcompare:restriction: URN if present


@dataclass(frozen=True, slots=True)
class ClassSetIndex:
    by_attachment: dict[tuple[str, str, str], ClassSetAttachment]
    # key = (attached_to, via_predicate, operator)


def build(snapshot: OntologySnapshot) -> ClassSetIndex: ...
```

Building it:

1. For each `?entity rdfs:domain ?target`, `?entity rdfs:range ?target`, `?entity rdfs:subClassOf ?target`, `?entity owl:equivalentClass ?target`:
   - If `?target` is a named IRI → not handled here (Components 07/08's territory).
   - If `?target` is a `urn:owlcompare:restriction:` URN AND that URN is typed as `owl:Restriction` → not handled here (Component 08's territory).
   - If `?target` is a `urn:owlcompare:restriction:` URN that is typed as `owl:Class` or `rdfs:Datatype` (anonymous class expression, not a restriction) AND has `owl:unionOf ?listURN` or `owl:intersectionOf ?listURN`: **this is our case.**
2. For each match:
   - Resolve `?listURN` through Component 04's collapsed list representation to get the member IRIs in order.
   - Filter to named IRIs (skip blank nodes, skip nested URNs — those become "complex" elsewhere).
   - Build the `ClassSetAttachment`.
3. **Flattening normalization:** if the same `(attached_to, via_predicate)` has *both* a direct named-IRI relationship AND a single-member union (which is malformed but possible), normalize to direct named-IRI form. If the union has exactly one member and there's no direct relationship, normalize to direct form. The index always presents the "logical" form.

### Part 2 — Diff the class set indexes

For each `(attached_to, via_predicate)` key present in either A or B:

1. **Case: Both A and B have a set attachment.**
   - If member sets are equal → no change.
   - If member sets differ:
     - Compute `removed_members = set_a - set_b`, `added_members = set_b - set_a`.
     - If `len(removed) == 0 and len(added) > 0` → `<context>_union_added` per added member, OR one `<context>_union_changed` carrying full before/after if multiple members.
     - If `len(added) == 0 and len(removed) > 0` → symmetric.
     - If both → one `<context>_union_changed` carrying full before/after.
2. **Case: A has a set; B has only a single named relation** (the union flattened to one member).
   - This is the flattening case. Compare A's members to {B's single member}.
   - Treat as set diff with the bare member as a one-element set.
   - Likely outcome: one or more `<context>_union_removed` entries.
3. **Case: A has only a single named relation; B has a set** (unflattening).
   - Symmetric. `<context>_union_added` for each member added beyond what A had.
4. **Case: Only A has the attachment.**
   - Whole structure removed. Emit `<context>_union_removed` for each member, or a single change with full before set.
5. **Case: Only B has the attachment.**
   - Whole structure added. Symmetric.

**Q1 resolution:** one change kind per `(via_predicate, action)` combination. So the full kind set is:

- `domain_union_changed`, `domain_union_added`, `domain_union_removed`
- `range_union_changed`, `range_union_added`, `range_union_removed`
- `subclass_union_changed`, `subclass_union_added`, `subclass_union_removed`
- `equivalent_class_union_changed`, `equivalent_class_union_added`, `equivalent_class_union_removed`

Twelve new kinds total.

**Intersection vs union:** for v1, treat `owl:intersectionOf` with the same logic and same kind names — the operator is recorded in `details.operator`. The semantic difference between union and intersection matters for severity (intersection is generally narrower; union is broader), which the severity classifier can read from details.

### Part 3 — Datatype facet index

`_datatype_facet_index.py` handles the `owl:onDatatype` + `owl:withRestrictions` pattern:

```python
@dataclass(frozen=True, slots=True)
class DatatypeFacets:
    """Decoded datatype facet restriction on a property's range."""
    property_iri: str
    base_datatype: str            # e.g., "xsd:decimal"
    min_inclusive: Decimal | int | None
    max_inclusive: Decimal | int | None
    min_exclusive: Decimal | int | None
    max_exclusive: Decimal | int | None
    length: int | None
    min_length: int | None
    max_length: int | None
    pattern: str | None
    raw_urn: str | None


def build(snapshot: OntologySnapshot) -> dict[str, DatatypeFacets]: ...
```

For each property where `rdfs:range` points to an anonymous URN typed as `rdfs:Datatype` with `owl:onDatatype` + `owl:withRestrictions`:

1. Resolve the URN through Component 04's reification.
2. Read `owl:onDatatype` for the base datatype.
3. Read `owl:withRestrictions` as a list of facet pairs (e.g., `[{xsd:minInclusive 0.0}, {xsd:maxInclusive 327670.0}]`).
4. Decode each facet into the structured `DatatypeFacets` record.

Diffing produces these kinds:
- `datatype_facet_added` — a previously-unfaceted range gained a facet (e.g., `xsd:decimal` → `xsd:decimal [min 0]`).
- `datatype_facet_removed` — symmetric.
- `datatype_facet_changed` — a facet's value shifted (e.g., `min 0 → min 100`).
- `datatype_base_changed` — the base datatype changed (`xsd:decimal → xsd:integer`), with all facets preserved or shifted.

Severity for datatype facets:

| Change | Severity |
|--------|----------|
| Facet added (tightening constraint) | `breaking` |
| Facet removed (relaxing constraint) | `non_breaking` |
| Facet tightened (e.g., `min 0 → min 100`) | `breaking` |
| Facet relaxed (e.g., `min 100 → min 0`) | `non_breaking` |
| Base datatype changed | `breaking` |

### Part 4 — `dcterms:isReplacedBy` slice

`replaced_by.py` is the simplest of the four. It runs after rename detection so it can cross-reference.

For each entity that has a `dcterms:isReplacedBy ?target` triple in B that wasn't in A (or vice versa):

1. Emit `replaced_by_set` (added) or `replaced_by_unset` (removed).
2. `details.target_iri` is the replacement IRI.
3. **Cross-check (Q2 resolution):** if `target_iri` matches any rename in `renames_applied` where the entity itself is the `before_iri`, set `details.matches_detected_rename = True`. Otherwise `False`. This is informational only — it doesn't change severity.

**Severity:** `replaced_by_set` is `non_breaking` (curator-asserted soft-deprecation signal; doesn't break existing valid data, but signals downstream consumers should migrate). `replaced_by_unset` is `info`.

### Subsumption

Each of the four parts subsumes the corresponding Layer 0 triples:

- Class set changes subsume: the `owl:unionOf ?listURN` triples, the `?listURN rdf:first ?member` / `rdf:rest ?next` triples for affected list cells, and the `?restrictionURN rdf:type owl:Class` triple if the URN was net-removed.
- Datatype facet changes subsume: the `owl:onDatatype` triple, each `[xsd:minInclusive ...]` facet triple set, `owl:withRestrictions ?listURN` and the list cells.
- `replaced_by_set` subsumes the `dcterms:isReplacedBy` triple_added (or removed).

After this component, the era_evolution-style "Layer 0 unexplained = 0" goal extends to ontologies with union-based domains/ranges — they should now show 0 unexplained too.

## Summary and details formatting

### Class set changes — summary patterns

```
"Domain union: era:axleSpacingDistance now includes era:VehicleTypeOriginal (added) and excludes era:VehicleType (removed) — was {era:VehicleType, era:VehicleTypeConfigParameterSet}, now {era:VehicleTypeConfigParameterSet, era:VehicleTypeOriginal}"
```

Too verbose. Simpler patterns by case:

- **Added member only:** `"Domain expanded on era:axleSpacingDistance: + era:VehicleTypeOriginal"`
- **Removed member only:** `"Domain narrowed on era:axleSpacingDistance: - era:VehicleType"`
- **Both:** `"Domain changed on era:axleSpacingDistance: + era:VehicleTypeOriginal, - era:VehicleType"`
- **Flattening (multi-member → single):** `"Domain simplified on era:axleSpacingDistance: now era:VehicleType only (was union of {era:VehicleType, era:VehicleTypeConfigParameterSet})"`
- **Unflattening (single → multi-member):** `"Domain extended on era:axleSpacingDistance: now union of {era:VehicleType, era:VehicleTypeOriginal} (was era:VehicleType)"`

Patterns are analogous for `range`, `subclass`, and `equivalent_class`. Specifically for subclass:

- `"era:TemporalFeature gained superclass via union: + time:TemporalScenario"`
- `"era:TemporalFeature simplified subclass: now time:TemporalDuration only (was union)"`

### Class set changes — details dictionary

```python
details = {
    "change_id": "structural:domain_union_changed:...",
    "entity_iri": "...",
    "via_predicate": "rdfs:domain",
    "operator": "unionOf" or "intersectionOf",
    "members_before": [iri1, iri2, ...],     # sorted
    "members_after": [iri1, iri3, ...],
    "added_members": [iri3],                 # set difference, for convenience
    "removed_members": [iri2],
    "shape_change": "stable" | "flattened" | "unflattened",
    "subsumes": [<layer0 change_ids>],
}
```

### Datatype facet changes — summary patterns

- `"Range tightened on era:dNvovtrp: xsd:decimal [min 0, max 327670 → min 0, max 100000]"` (facet shift)
- `"Range constrained on era:dNvovtrp: xsd:decimal [min 0] added"` (facet added)
- `"Range loosened on era:dNvovtrp: max 327670 removed"` (facet removed)
- `"Range base changed on era:dNvovtrp: xsd:decimal → xsd:integer"` (base swap)

details = {

- `"era:TSIMagneticFields marked as replaced by era:tsiMagneticFields"`

## Severity rules

| Kind | Severity | Notes |
|------|----------|-------|
| `domain_union_added` | `non_breaking` | Broader applicability |
| `domain_union_removed` | `breaking` | Narrower applicability — existing instances may no longer satisfy |
| `domain_union_changed` (members added + removed) | `breaking` | Mixed — defensive |
| `range_union_added` | `non_breaking` | Broader values accepted |
| `range_union_removed` | `breaking` | Narrower values accepted |
| `range_union_changed` (mixed) | `breaking` | |
| `subclass_union_added` | `non_breaking` | New parent in union |
| `subclass_union_removed` | `breaking` | Lost parent in union |
| `subclass_union_changed` (mixed) | `breaking` | |
| `equivalent_class_union_*` | always `breaking` | Semantic identity shift |
| `datatype_facet_added` | `breaking` | New constraint |
| `datatype_facet_removed` | `non_breaking` | Constraint relaxed |
| `datatype_facet_changed` (tightening) | `breaking` | |
| `datatype_facet_changed` (relaxing) | `non_breaking` | |
| `datatype_base_changed` | `breaking` | |
| `replaced_by_set` | `non_breaking` | Curator-asserted soft deprecation |
| `replaced_by_unset` | `info` | Removing a replacement signal |

The flattening / unflattening shape changes themselves don't bump severity — what matters is the *member set* difference. Flattening a 2-member union to a single member where the surviving member matches what's logically equivalent doesn't change severity; the removed member's severity contribution does.

## Edge cases & failure modes

- **Empty union list** (`owl:unionOf rdf:nil`): malformed but possible. Treat as no attachment; emit nothing. Log INFO.
- **Single-member union flattening to a different member** (A is `union(X, Y)`, B is just `Z`): two removed members (X, Y) and one added (Z). Emit as `<context>_union_changed` carrying full before/after.
- **Nested anonymous structure within a union** (a union containing another anonymous restriction): the nested structure is left as `complex_class_expression_changed` (Component 08's existing kind). The outer union's other named members are still tracked normally.
- **Intersection of restrictions** (`owl:intersectionOf` containing only `owl:Restriction` URNs, no named classes): not handled here. Stays as Component 08's `complex_class_expression_changed`.
- **`owl:unionOf` AND `owl:intersectionOf` on the same entity for the same predicate** (e.g., domain has both forms): malformed; pick the first encountered, log INFO.
- **`dcterms:isReplacedBy` target that doesn't exist in either snapshot:** emit normally with `matches_detected_rename = False` and `target_existed_in_b = False` in details. Don't fail.
- **`dcterms:isReplacedBy` on a class that was renamed away** (the entity itself is gone in B; only A had the assertion): the entity-level `class_removed` (Component 06) handles it. Don't double-emit.
- **`dcterms:replaces` (the inverse direction):** out of scope for v1; could be added in a future component. Just `dcterms:isReplacedBy` for now.
- **Datatype facet with both `xsd:minInclusive` and `xsd:minExclusive` on the same datatype:** malformed but possible. Record both; severity = `breaking`.
- **Pattern facet** (`xsd:pattern`): captured in `DatatypeFacets.pattern` but no special diffing — a changed pattern is treated as `datatype_facet_changed` with `changed_facets = ["pattern"]`.

## Coordination with earlier components

- **Component 04 (canonicalization):** no changes needed. The decoder reads through the URN reification that Component 04 already produces.
- **Component 07 (hierarchy):** the existing hierarchy index already skips synthetic restriction URNs, so it doesn't fire on `subClassOf <urn:...>` triples — that's our domain now.
- **Component 08 (restrictions):** today, Component 08 sees an `urn:owlcompare:restriction:` URN that's typed as `owl:Class` (not `owl:Restriction`) and classifies it as `complex_class_expression_changed`. After Component 12.5, those URNs are decoded by `class_sets.diff` first; the `complex_class_expression_changed` fallback only fires for *truly* complex cases (nested intersections of restrictions, etc.).
- **Component 09 (annotations):** today, `dcterms:isReplacedBy` triples become `annotation_added/removed`. After Component 12.5, `replaced_by.diff` runs *after* annotations and *promotes* matching annotation changes to the dedicated kind. The annotation slice's emissions for those triples are *retracted* via registry coordination (the registry already supports "this layer 0 change is explained by"; we just need to make sure subsumption transfers from annotation to replaced_by when both would match).

This last point is delicate. Implementation note: `replaced_by.diff` runs *after* annotations.diff. It looks for `annotation_added/removed` changes already emitted whose predicate is `dcterms:isReplacedBy`, *removes them* from the result, and emits its own `replaced_by_set`/`replaced_by_unset` in their place. This requires the diff result to be mutable at this stage — which it is, until it's frozen for severity refinement.

## Out of scope (deliberately)

- `owl:oneOf` enumeration (lists of *individuals*, not classes). Different shape; small additional component if needed.
- `owl:complementOf` over anonymous unions (the complement of a union). Component 08 handles complement of named classes; nested case deferred.
- `owl:propertyChainAxiom` and `owl:hasKey` (ordered lists). Per Q3, out of scope for v1.
- `dcterms:replaces` (the inverse direction). Add in v1.1 if requested.
- SHACL shapes — they have their own structure, not addressed here.
- Reasoning to determine whether two unions are *semantically* equal even if their lexical form differs. Asserted-only diffing.

## Open questions

- [x] **Q1 (additional, resolved — adopted proposed):** A class set losing a member down to a single survivor (and flattening to a bare class) emits `<context>_union_removed`, not a new `union_simplified` kind. The shape change is recorded in `details.shape_change` (`stable` / `flattened` / `unflattened`); the visible change is the member loss. A single-member union is normalized to bare in the index (`_class_set_index.build` drops attachments with `< 2` named members), so the diff compares logical member sets regardless of how either side spells them.

- [x] **Q2 (additional, resolved — adopted proposed):** Severity is decided in this component, not Component 10. `unionOf` uses the listed defaults; `intersectionOf` swaps `added` / `removed` (added narrows → `breaking`; removed broadens → `non_breaking`). `equivalent_class_union_*` is always `breaking`; any mixed `*_changed` is `breaking`. Implemented in `class_sets._union_severity`; both directions are tested.

- [x] **Q3 (additional, resolved — adopted proposed):** The retraction pattern. `replaced_by.diff` emits `replaced_by_set` / `replaced_by_unset`, and the orchestrator removes the superseded `annotation_added` / `annotation_removed` / `annotation_changed` changes for the same `dcterms:isReplacedBy` triple (`replaced_by.supersedes_annotation`). The annotation slice stays oblivious to the predicate, so future predicate-specific promoters reuse the same mechanism.

All three open questions were resolved by adopting the proposed answers.

## Resolved design notes (added during implementation)

- **Component 04 is unchanged — datatype nodes stay blank nodes.** The spec's Part 1/Part 3 wording ("anonymous *URN* typed as `rdfs:Datatype`") implies datatype nodes are reified, but canonicalization only reifies `owl:Restriction` / `owl:Class` (so `owl:Class` unions become `urn:owlcompare:restriction:` URNs while `rdfs:Datatype` union and facet nodes stay canonicalized blank nodes). Rather than extend Component 04 (a cross-cutting change the spec said was unnecessary, with downstream effects on Components 06–08), both decoders read the *actual* canonical form: `ClassSetAttachment.raw_urn` / `DatatypeFacets.raw_urn` is `None` for the blank-node case (as the spec's `str | None` already anticipated). Subsumption matches Layer 0 changes by the node's n3 string (`class_sets._index_by_subject_n3`), which covers URIRef *and* blank-node subjects uniformly, so datatype facet/union structures still reach zero unexplained Layer 0.

- **Component 07 coordination was needed too, not just Component 08.** The subclass-union *flattening* case (v1 `subClassOf` union → v2 a bare named superclass) is the hierarchy slice's territory on the bare side, so Component 07 also consults `_class_set_index.owned_keys` and skips `(entity, rdfs:subClassOf)` keys a class set owns. Component 08 skips owned domain/range/equivalent keys and drops reified union/intersection class expressions before they reach `complex_class_expression_changed`. Both compute ownership directly from the graphs, so no orchestrator threading or slice-signature change was required, and `rename.re_diff_renamed_entities` (which re-runs these slices on sub-snapshots) is unaffected.

- **Class-set keys are derived from `owned_keys`, not `by_attachment`.** Because a single-member union normalizes to bare (no attachment), the diff iterates the owned keys (every union/intersection node, single-member included) and computes members straight from the graph (`_effective_members`), so a key that is bare on one side and a union on the other is still diffed and its triples subsumed.

- **No new Component 10 rule.** The intersection severity inversion (Q2) lives in this slice, and the existing Rule 6 (`subsumed-layer0-info`) already demotes the now-subsumed union/list/facet triples. The severity classifier needed no cross-cutting rule for the 18 new kinds.
