# Component 01: CLI Scaffold

## Identity

- **Component number:** 01
- **Name:** CLI scaffold
- **Module path:** `src/owlcompare/cli.py` (entry point), `src/owlcompare/__main__.py` (module run support), `src/owlcompare/_version.py` (version source), `src/owlcompare/exceptions.py` (typed exceptions), `src/owlcompare/logging_config.py` (logging setup)
- **Roadmap phase:** Phase 1
- **Depends on components:** none (this is the first concrete component)
- **Depended on by (planned):** all subsequent components plug into the CLI surface defined here

## Purpose

Establish the user-facing command-line shape, logging setup, exit code conventions, and exception hierarchy that every subsequent component will plug into. After this component, `owlcompare --help` is a real, professional-looking CLI. No actual diff logic yet — the `diff` subcommand exists as a stub that returns "not yet implemented" with a clear exit code.

What would break if we removed it: every subsequent component would need to invent its own CLI integration, logging discipline, and error-to-exit-code mapping. By centralizing here, we set the rhythm.

## Public API

The CLI commands are the public surface. All Python-level functions are internal except:

```python
# src/owlcompare/__init__.py
__version__: str  # exported for programmatic access

# src/owlcompare/cli.py
def main(argv: list[str] | None = None) -> int:
    """Entry point. Returns exit code. Used by tests and the console script."""
```

Typer-driven CLI commands:

```
owlcompare [--version] [-v|--verbose] [-q|--quiet] <COMMAND> [ARGS...]

Commands:
  diff      Compare two ontologies (stub in v1; not yet implemented)
  version   Print the version and exit
```

`diff` subcommand signature (stub):

```
owlcompare diff [OPTIONS] ONTOLOGY_A ONTOLOGY_B

Arguments:
  ONTOLOGY_A    Path or URL to the baseline ontology  [required]
  ONTOLOGY_B    Path or URL to the comparison ontology  [required]

Options:
  --format [json|markdown|html|junit]   Output format  [default: json]
  --out PATH                            Output file (default: stdout for json/markdown)
  --help                                Show this message and exit
```

The stub validates that A and B exist (or look like URLs) and that --format is one of the listed values, then exits with code 2 and the message "diff is not yet implemented (planned for Phase 2)".

## Internal design

### Module layout

```
src/owlcompare/
├── __init__.py             # exports __version__
├── __main__.py             # enables `python -m owlcompare`
├── _version.py             # single source of truth for the version
├── cli.py                  # Typer app + main()
├── exceptions.py           # OwlCompareError hierarchy
└── logging_config.py       # configure_logging()
```

### `_version.py`

Single source of truth. Define:

```python
__version__ = "0.0.1"
```

Re-export from `__init__.py`. `pyproject.toml`'s version is read dynamically from this file (via Hatchling's `dynamic = ["version"]` + `tool.hatch.version.path = "src/owlcompare/_version.py"`).

### `exceptions.py`

The exception hierarchy that all future components extend:

```python
class OwlCompareError(Exception):
    """Base for all owlcompare errors. Carries an exit_code attribute."""
    exit_code: int = 1

class UsageError(OwlCompareError):
    """User-facing input error (bad CLI args, missing file)."""
    exit_code: int = 2

class LoadError(OwlCompareError):
    """Failure to load or parse an ontology."""
    exit_code: int = 3

class DiffError(OwlCompareError):
    """Failure during diff computation."""
    exit_code: int = 4

class ReportError(OwlCompareError):
    """Failure during report generation."""
    exit_code: int = 5

class NotImplementedYetError(OwlCompareError):
    """A planned feature stub. Used by Layer 2/3 stubs and the diff stub in v1."""
    exit_code: int = 2
```

### `logging_config.py`

```python
def configure_logging(verbosity: int) -> None:
    """
    verbosity: 0 = WARNING (default), 1 = INFO (-v), 2+ = DEBUG (-vv).
    Honors OWLCOMPARE_LOG_LEVEL env var if set (overrides verbosity).
    Format: "<level> <module>: <message>", colored via rich if stderr is a TTY.
    """
```

Use `rich.logging.RichHandler` when stderr is a TTY; fall back to a plain formatter otherwise (CI logs). No print() anywhere.

### `cli.py`

- Build a `typer.Typer` app with `no_args_is_help=True`, `add_completion=False`, `pretty_exceptions_show_locals=False`.
- Register the `diff` and `version` subcommands.
- Top-level callback handles `--verbose`/`--quiet` and calls `configure_logging`.
- `main(argv)` wraps the Typer app, catches `OwlCompareError` subclasses, logs them, and returns their `exit_code`. Any other exception → log full traceback at DEBUG, log a friendly message at ERROR, return 1.
- The console script entry point in `pyproject.toml` is `owlcompare = "owlcompare.cli:main"`.

### `__main__.py`

```python
from owlcompare.cli import main
import sys
if __name__ == "__main__":
    sys.exit(main())
```

## Exit codes (canonical, do not change without updating this spec)

| Code | Meaning |
|------|---------|
| 0 | Success, no breaking changes (when implemented) |
| 1 | Generic error (uncaught exception) |
| 2 | Usage error or feature-not-implemented stub |
| 3 | Load error (bad ontology, missing file, parse failure) |
| 4 | Diff computation error |
| 5 | Report generation error |
| 6 | Severity config invalid (malformed TOML, unknown schema_version/severity, missing kind_pattern) — Component 10. A missing config *file* is a usage error (2), not 6. |
| 10 | Diff completed but breaking changes found (active since Component 05; survives severity refinement in Component 10) |

> **Note:** the table above is the original Component 01 sketch. The contract
> evolved naturally during later components; for the authoritative v1 exit-code
> contract as actually implemented, see `docs/DESIGN_DECISIONS.md` § DD-025 (and
> the user-facing `docs/reference/exit-codes.md`).

## Edge cases & failure modes

- **No arguments:** show top-level help and exit 0 (Typer's `no_args_is_help=True`).
- **`--version` flag:** print version to stdout, exit 0. (Plus the `version` subcommand for symmetry.)
- **Unknown subcommand:** Typer's default behavior — error message to stderr, exit 2.
- **`diff` with missing positional argument:** Typer reports it, exit 2.
- **`diff` with --format=invalid:** Typer reports it (Enum-validated), exit 2.
- **`diff` with valid args:** raise `NotImplementedYetError("diff is not yet implemented (planned for Phase 2)")` → exit 2.
- **`OWLCOMPARE_LOG_LEVEL=DEBUG`:** overrides `--verbose`/`--quiet`.
- **KeyboardInterrupt:** caught at top level, prints "Interrupted." to stderr, exit 130 (standard SIGINT convention).

## Out of scope (deliberately, to keep this component small)

- Actual diff computation (Phase 2).
- Reading ontologies (Component 02).
- Output file writing (Component 14+).
- Auto-completion scripts (Typer supports them; we'll add later if requested).
- A `report` or `validate` subcommand (not in our roadmap).
- Config file support (deferred; CLI flags + env vars are sufficient through v1).

## Open questions

- [ ] **Q1:** Should `--version` print just the version string (`0.0.1`) or include the program name (`owlcompare 0.0.1`)?
  **Proposed:** `owlcompare 0.0.1\n`. Matches `git --version`, `python --version`, common convention.
- [ ] **Q2:** Should the `diff` stub validate that input paths exist before raising NotImplementedYetError?
  **Proposed:** No — validation belongs to Component 02 (loader). The stub fails fast on "not implemented" regardless of file existence. Tests should not require any file to exist.

If you have a preference, override before implementing. Otherwise, proceed with the proposed answers.
